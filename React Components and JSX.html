React Components and JSX

Theory

Congratulations! You've mastered creating your first React project. We've covered the project structure, so now let's start writing some code.
In this lecture, we'll explore one of React's most important concepts: Components. Components are reusable building blocks used to create user interfaces. It's good practice to create a separate
.jsx
file for each component, though this depends on the component's complexity and how often it will be reused. Before we start coding, let's modify the project structure.

Project Structure

A new Vite-based React project comes with several essential files and folders. A well-structured project is crucial for maintainability. Our main goal is to ensure that other developers, even those who never communicate with us, can continue working on the project. This requires clear documentation and an organized project structure. For that let’s create directories called
components
,
hooks
,
layouts
,
pages
,
services
and so on.
To create these directories, we can do it via Command line or inside the IntelliJ by right clicking the src directory and creating the directories. In command line:
cd src
​
mkdir components hooks layouts pages services

Inside
components
, we store reusable UI components. For each component, you can create two files: one for JavaScript and one for CSS. In this course, I will only create JavaScript files since I'll be using Tailwind for styling.
Inside
layouts
we store layout components like Sidebar, Navbar, Footer, etc. Inside
pages
we store all the page components such as Home, About, and Dashboard. When building your application, first create components in the components directory, then import them into your layouts, which can then be imported into your pages.

What Are Components?

Look at this dashboard and identify which components could be reused across multiple pages. While there are many examples, one clear case is the sidebar navigation, which appears on every page as part of the Layout component. The sidebar contains 8 navigation links, so we'll create a single reusable component for it in the
components
directory. The cards displaying numbers with circular diagrams can all be combined into a single reusable component.
You might wonder how these cards can be a single component when they display different data. The answer is simple: props. We will get back to props later.
As Maximilian explains in his book: When working with React, it’s especially important to keep your code manageable and work with small, reusable components because React components are not just collections of HTML code. Instead, a React component also encapsulates JavaScript logic and often also CSS styling. For complex user interfaces, the combination of markup (JSX), logic (JavaScript), and styling (CSS) could quickly lead to large chunks of code, thus making it difficult to maintain that code. Think of a large HTML file that also includes JavaScript and CSS code. Working in such a code file wouldn’t be a lot of fun.
In essence, React development revolves around working with numerous components. You break down your code into small, manageable building blocks and combine them to create the complete user interface—this is one of React's fundamental strengths.

What Does a React Component Look Like?

Here we have a component created inside the
component
directory. The file is named
SimpleCounter.jsx
. While you're familiar with
.js
files,
.jsx
indicates that this file contains JSX code.
import { useState } from "react"; const SimpleCounter = () => { const [count, setCount] = useState(0); return ( <div> <h1>Simple Counter</h1> <p>Count: {count}</p> <button onClick={() => setCount(count + 1)}>Increment</button> <button onClick={() => setCount(count - 1)}>Decrement</button> </div> ); }; export default SimpleCounter;
​
Don't panic! You don't need to understand all the code yet. Let me break it down: we've created a function by declaring a const with a function name. This function doesn't take any parameters (which we call "props" in React, as mentioned earlier). After that, we have a return statement. Inside the return, we see familiar HTML-like code—but this is actually JSX. Every component has its own div container, and inside it we have an h1, a p tag, and two buttons. Notice the
{count}
inside the p tag—this displays the variable's value. While this isn't easily done in pure HTML, it's simple in JSX, similar to Python's f-strings. And we have
export default SimpleCounter;
. This allows other files to import and use this component.
import SimpleCounter from "./SimpleCounter"; function App() { return ( <div> <SimpleCounter /> </div> ); } export default App;
​
In this example, we've imported the
SimpleCounter
component from the
./SimpleCounter
file and used it within the App component. Think of it this way: it's similar to Python functions, where each function has its own
.py
file and you import them into other files whenever you need to use them.

Passing Data Between Components

Now that we've created components, let's explore how to display different data in each instance. Consider Instagram's navigation bar as an example. It has five links: Home, Search, Reels, Store, and Profile. Instead of creating five separate components, Instagram likely uses a single component with different icons. Let's build upon our previous example.
Let's modify our
SimpleCounter
component to accept different initial count values and custom button labels. In the App component, we have imported the
SimpleCounter
component and passed it attributes for
initialCount
,
incrementLabel
, and
decrementLabel
.
import SimpleCounter from "./SimpleCounter"; function App() { return ( <div> <SimpleCounter initialCount={5} incrementLabel="Add One" decrementLabel="Remove One" /> <SimpleCounter initialCount={10} incrementLabel="Increase" decrementLabel="Decrease" /> </div> ); } export default App;
​
In the
SimpleCounter
component, we add props inside the function's parameter brackets. Without defining the
props
parameter in a component function, you won't be able to access the
props
data in that component. The
props
argument is an object that React automatically provides, containing all the attributes you passed to your component as its properties.
import { useState } from "react"; const SimpleCounter = ({ initialCount, incrementLabel, decrementLabel}) => { const [count, setCount] = useState(initialCount); return ( <div> <h1>Simple Counter</h1> <p>Count: {count}</p> <button onClick={() => setCount(count + 1)}>{incrementLabel}</button> <button onClick={() => setCount(count - 1)}>{decrementLabel}</button> </div> ); }; export default SimpleCounter;
