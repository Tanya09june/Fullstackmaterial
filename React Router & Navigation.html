React Router & Navigation

Theory

We have now learned about creating components, handling events, and using hooks like useState and useContext.
useState
adds state variables to your component, while
useContext
lets a component receive information from distant parents without passing it through props. We've also covered conditional rendering.
Now that we have built our components, let's focus on creating pages. As covered in Lecture 7 about project structure, we have a dedicated directory for pages. This is where we create all the pages our application needs, utilizing our reusable UI components.

Imagine with me

Imagine we have a food delivery web app with pages like Home, Nearby, Cart, and Settings. While we could manage page views using conditional rendering and state, this approach becomes complex for developers. Moreover, without proper URL paths, users cannot share specific pages—like the food they're planning to order—with their friends. If we refresh the page, everything will be lost and we'll have to start from the beginning. Furthermore, this approach prevents users from using their browser's back and forward buttons to navigate through their browsing history.
One page is not enough for our web app. For that we need for link or different URL path for each page. Right? So if the user wants to share the food what is ordering the URL should look like this:
www.hungerfood.com/restaurants/grillistanbul/menu/adanakebab
www.hungerfood.com/restaurants/grillistanbul/menu/lahmacun
www.hungerfood.com
(Domain)
This represents the main domain of the website.
hungerfood.com
serves as the primary domain name, indicating a food-focused website that likely offers restaurant listings, food delivery services, or menus.
1.
/restaurants/
(Path)
This segment indicates that the page is related to restaurants.
It is a directory where restaurant-related content is organized.
2.
grillistanbul/
(Subdirectory)
This refers to a specific restaurant named "Grill Istanbul".
It means the website has individual pages for different restaurants.
3.
/menu/
(Subdirectory)
This suggests that the page is displaying the menu of the restaurant.
There might be other sections like
/reviews/
,
/location/
, etc., on the website.
4.
adanakebab
(Page or Item)
This is a specific dish from the restaurant's menu, Adana Kebab.
Clicking this URL may take the user to a detailed page about the Adana Kebab dish, including its price, ingredients, and ordering options.
To implement this URL structure, we need a third-party React library called React Router. To install this package, run the following command in your project directory
npm install react-router-dom

Getting Started with React Router

After installing the package and organizing your project structure, you'll need to set up React Router in
App.jsx
.
import { BrowserRouter, Routes, Route } from "react-router-dom"; import AdminDashboardPage from "./pages/AdminDashboardPage.jsx"; import CheckoutPage from "./pages/CheckoutPage.jsx"; import CartPage from "./pages/CartPage.jsx"; import HomePage from "./pages/HomePage.jsx"; function App() { return ( <BrowserRouter> <Routes> <Route path="/" element={<HomePage />} /> <Route path="/restaurants" element={<RestaurantsPage />} /> <Route path="/markets" element={<MarketsPage />} /> <Route path="/cart" element={<CartPage />} /> <Route path="/settings" element={<SettingsPage />} /> </Routes> </BrowserRouter> ); } export default App;
​
In
App.js
, we import three essential components from React Router: BrowserRouter, Routes, and Route. We also import our page components that need specific URL paths. In the return statement, we implement these React Router components to set up our routing structure. Let's examine the code:
BrowserRouter
This main component enables routing functionality throughout a React application.
It listens to the browser’s URL and renders the correct page based on the current route.
Example: If you type
/orders
in the URL,
BrowserRouter
will match that and load the
Orders
component.
Routes
This is a container for all
<Route>
components.
It ensures that only one matching route is rendered at a time.
Route
Defines a specific path and which component should be displayed when the user visits that path.
Each
<Route>
has:
A
path
(URL it matches)
An
element
(component to render)

Adding Page Navigation

Now that we've modified
App.jsx
, we need to take another step. To let users navigate between pages without typing URLs manually, websites typically include navigation links using the
<a>
HTML element.
Is using the
<a>
element appropriate here? Let's examine this. The
<a>
element redirects to the next page and reloads the website each time a user clicks a link. This means the browser sends a new HTTP request to the server for every click. As a result, we lose all our states. If a user increases the quantity of a dish and accidentally navigates away, all progress is lost and they need to increase the amount again.
That's why React Router provides the
Link
component. Unlike regular links, it doesn't refresh the page. Instead, it updates the URL and changes the view dynamically. This makes navigation feel instant, keeping the app fast and responsive.
import { Link } from "react-router-dom"; function Navbar() { return ( <nav> <Link to="/">Home</Link> <Link to="/restaurants">Restaurants</Link> <Link to="/markets">Markets</Link> <Link to="/cart">Cart</Link> <Link to="/settings">Settings</Link> </nav> ); } export default Navbar;
​
Here we have a basic Navbar component without any styling to keep the code simple. The
Link
component uses the "to" prop to specify which path the page should navigate to when clicked.
Since we want the navigation bar to appear on every page—whether the user visits Home, Restaurants, Markets, Cart, or Settings. —we can place the
Navbar
component directly in
App.jsx
.
import { BrowserRouter, Routes, Route } from "react-router-dom"; import HomePage from "./pages/HomePage.jsx"; import RestaurantsPage from "./pages/RestaurantsPage.jsx"; import MarketsPage from "./pages/MarketsPage.jsx"; import CartPage from "./pages/CartPage.jsx"; import SettingsPage from "./pages/SettingsPage.jsx"; import NotFoundPage from "./pages/NotFoundPage.jsx"; import Layout from "./components/Navbar.jsx"; function App() { return ( <BrowserRouter> <Routes> <Route path="/" element={<Navbar />}> <Route index element={<HomePage />} /> <Route path="/restaurants" element={<RestaurantsPage />} /> <Route path="/markets" element={<MarketsPage />} /> <Route path="/cart" element={<CartPage />} /> <Route path="/settings" element={<SettingsPage />} /> <Route path="*" element={<NotFoundPage />} /> </Route> </Routes> </BrowserRouter> ); } export default App;
​
<Route path="/" element={<Navbar />}>
: Creates a route for the root URL (
/
) and renders the
Navbar
component.
<Route index element={<HomePage />} />
: Acts as a child of the root route and renders the
HomePage
component when users visit the root URL without any sub-paths.
When you visit the website, both the navbar and HomePage components will be rendered by default. The navbar remains visible across all pages—including HomePage, Restaurants, Markets, Cart, and Settings.
Additionally, I've added
<Route path="*" element={<NotFoundPage />} />
, which means if the user navigates to an unspecified path, React will render the
<NotFoundPage />
component. The Not Found page won't display the navbar since it's defined outside the root Route.
import { Link, Outlet } from "react-router-dom"; function Navbar() { return ( <> <nav> <Link to="/">Home </Link> <Link to="/restaurants">Restaurants </Link> <Link to="/markets">Markets </Link> <Link to="/cart">Cart </Link> <Link to="/settings">Settings </Link> </nav> <Outlet /> </> ); } export default Navbar;
​
In the Navbar component, we place the
<Outlet />
component from react-router-dom outside the nav tags. This component acts as a placeholder in a parent route to render the child routes.

Dynamic Routing with URL Parameters

When a user selects a restaurant, where should the website redirect them? Rather than creating individual pages for each restaurant, we use a single restaurant page that acts as a template. This template displays different text and images depending on which restaurant is selected. We also need to modify
App.jsx
.
import { BrowserRouter, Routes, Route } from "react-router-dom"; import HomePage from "./pages/HomePage.jsx"; import RestaurantsPage from "./pages/RestaurantsPage.jsx"; import MarketsPage from "./pages/MarketsPage.jsx"; import CartPage from "./pages/CartPage.jsx"; import Details from "./pages/Details.jsx"; import SettingsPage from "./pages/SettingsPage.jsx"; import NotFoundPage from "./pages/NotFoundPage.jsx"; import Layout from "./components/Navbar.jsx"; function App() { return ( <BrowserRouter> <Routes> <Route path="/" element={<Navbar />}> <Route index element={<HomePage />} /> <Route path="/restaurants" element={<RestaurantsPage />} /> <Route path="/restaurants/:restaurantId" element={<Details />} /> <Route path="/markets" element={<MarketsPage />} /> <Route path="/cart" element={<CartPage />} /> <Route path="/settings" element={<SettingsPage />} /> <Route path="*" element={<NotFoundPage />} /> </Route> </Routes> </BrowserRouter> ); } export default App;
​
Let me remind you with this URL
www.hungerfood.com/restaurants/grillistanbul
. We have restaurant called
grillistanbul
. Grill Istabul should be stored in our database. Grill Istanbul has also id.
Let me briefly explain some Backend and Frontend concepts. While we'll cover these in detail later, there's one key thing to understand now. The example shown here is from Wolt, a food delivery app.
The page shows six restaurant cards, each displaying details like pictures, names, slogans, delivery prices, and times. Each card is an instance of a
RestaurantCard
component. Each restaurant has a unique ID in the database. When users click a card, the app updates the URL with that restaurant's ID through React Router. The
Details
component then fetches and displays that specific restaurant's information via an API request.
<Route path="/restaurants/:restaurantId" element={<Details />} />
​
The route
/restaurants/:restaurantId
is a dynamic path, where
:restaurantId
acts as a placeholder (a URL parameter). This placeholder will be replaced with the actual restaurant ID when a user clicks on a restaurant card.
Here's a simplified example of the
Details
component, before we add the API request functionality. Will cover API request later.
import { useParams } from "react-router-dom"; const Details = () => { const { restaurantId } = useParams(); return <div>Displaying details for restaurant {restaurantId}</div>; };
​
useParams()
is a hook provided by React Router that extracts dynamic parameters from the current URL. When we create an API request, we take the restaurantId from the URL using the useParams hook, then send an API request with that id to fetch the specific restaurant's details.
