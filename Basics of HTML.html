What is HTML?

HTML is like the foundation of a house—it’s where everything starts. Think of a webpage as a beautifully designed home. HTML is the blueprint and concrete slab that holds it all together, giving structure to the text, images, videos, and links you see online. Without HTML, the web would be like a house of cards—unstructured and ready to collapse into a messy pile of raw content.
HyperText is the magic that connects your pages, like doorways linking different rooms in a house. And “Markup Language”? That’s the toolkit of tags used to define everything from headers (your roof) to paragraphs (the walls) and images (the decor). It’s the solid base that web designers and browsers rely on to make the internet a functional, beautiful space.
Now, here’s something important: HTML isn’t a programming language. It doesn’t “do” things like logic or calculations—it’s all about structure and organization, like laying out the rooms and walls of a building.

Let's explore the structure of this HTML document. When you create a new HTML file, these elements are typically included automatically by the IDEA:
Document Type Declaration (
<!DOCTYPE html>
):
The first line,
<!DOCTYPE html>
, is a declaration that informs the browser which version of HTML the document uses. This particular declaration specifies HTML5, the current standard for modern web development.
HTML Element (
<html>
and
</html>
):
The
<html>
element acts as the root container for the entire document. All other elements, including
<head>
and
<body>
, are nested inside it. This is the root element of the HTML document, meaning it cannot be nested within any other tag.
Head Section (
<head>
and
</head>
):
The
<head>
section contains metadata about the document that is not directly displayed on the web page. It typically includes:
<meta charset="UTF-8">
: Specifies the character encoding as UTF-8, supporting a wide range of characters from different languages.
<title>
: The
<title>
tag sets the title of the web page, which is displayed in the browser tab or as a bookmark title.
Links to CSS Files: You can include external stylesheets using the
<link>
tag to define the visual presentation of your page. For example: This line links the
styles.css
file to the document, applying its styles to the content in the
<body>
.
<link rel="stylesheet" href="styles.css">
We will cover it more later
ALT
​
Links to JavaScript Files: If you have JavaScript files, you can include them in the
<head>
(or at the end of the
<body>
for performance optimization) using the
<script>
tag. For example:
<script src="script.js"></script>
We will cover it more later
ALT
​
Body Section (
<body>
and
</body>
)
The
<body>
tag contains all the content that will be displayed in the browser window. This includes text, images, videos, and other elements. In this example, the placeholder text "Content here" represents the page's visible content.

Let’s explain more about Text Elements:
Headings (
<h1>
and
<h2>
):
<h1>
: Represents the most important heading on the page, used for the main title. In this case, it is "Finland". By default, browsers render it as large and bold text.
<h2>
: Represents subheadings or second-level headings, such as "General Information" and "Second Information". It provides a clear hierarchy of content and helps assistive technologies and search engines understand the document's structure.
Paragraphs (
<p>
):
<p>
: Defines a block of text. Paragraphs are block-level elements and are visually separated by some space above and below.
Bold Text (
<b>
):
<b>
: Stands for "bold," used to make text visually distinct from the surrounding content without implying additional importance.

Validating Document

Validating HTML documents ensures they adhere to the rules of the specified HTML version. This process improves consistency across browsers, speeds up display, and enhances accessibility. While browsers will attempt to render documents with errors, deviating from standards can lead to unpredictable behavior. Validators, software tools for checking HTML, are essential because manual validation is prone to errors.
Validators check for key issues such as:
Missing or incorrect DOCTYPE declarations, which specify the HTML version to validate against.
Missing character encoding declarations.
Absence of required rules and attributes.
Use of non-standard elements.
Mismatched or improperly nested tags.
Typos and other minor errors.
One of the best web-based validators is html5.validator.nu, which can validate files or live web pages. It generates detailed reports highlighting errors, the source of the problem, and suggestions for corrections. Additionally, tools like browser developer tools (e.g., in Chrome and Firefox) and built-in validators in some code editors provide on-the-fly validation to help developers catch and correct issues efficiently.
