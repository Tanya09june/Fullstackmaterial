Conditional Rendering and useContext Hook

Theory

Imagine a system with multiple roles—admin, teacher, student, and so on—all running under the same URL. How does this work? Let's take Amazon as an example. Amazon is an e-commerce platform where you can search for and buy items. But there's also someone on the other end listing these items for sale. So what's happening here?
There are two roles here: seller and purchaser. The seller lists items while the purchaser buys them. The UI that sellers see differs from what purchasers see. For example, sellers have an "Add Product" button, but purchasers don't. In essence, while sellers and purchasers create accounts in the same app, they each get a different view. How does this work from a programming perspective? Note that this is a simplified example to illustrate the concept, not necessarily how Amazon actually works.

Conditional Rendering

When searching for a flight, you begin by entering your departure location (From), destination (To), travel dates (Dates), and passenger count (Passengers). After clicking the Search button, this information goes to the airline's server for processing.
The system then scans its database for matching flights, checking current seat availability, prices, and active promotions. For multiple matches, it sorts the results by departure time, flight duration, price, and route type (direct or connecting). Finally, you see these organized flight options displayed on your screen.
This process can take considerable time to display results. To improve the user experience, we should notify users when their request is being processed by the backend and while flight options are being retrieved. The user interface typically includes an attractive loading animation during this time. I really like Qatar Airways' loading page
There are several ways to accomplish this. I will demonstrate two approaches.
let a = 1; if (someCondition) { a = 2; }
​
This is a simple if statement, which you should be familiar with from Python and JavaScript. This same code can be written like this:
const a = someCondition ? 2 : 1;
​
If the condition is true, the variable
a
is assigned the value after the
?
mark (in this case, 2). If the condition is false, it's assigned the value after the
:
(in this case, 1). It's straightforward, isn't it?
In Qatar Airways' case, their code might look something like this:
import { useState } from "react"; function BookingPage() { const [loading, setLoading] = useState(false); function handleShowLoading() { setLoading(true); } let content; if (loading) { content = <p>Loading...</p>; } else { content = <FlightSearch />; } return ( <div> <button onClick={handleShowLoading}>Show Loading</button> {content} </div> ); } export default BookingPage;
​
A more likely implementation would look like this
import React, { useState } from "react"; const BookingPage = () => { const [loading, setLoading] = useState(false); return ( <div> {loading ? <p>Loading...</p> : <FlightSearch />} </div> ); }; export default BookingPage;
​
Be aware that there are situations where using "if" statements becomes more complex. You can use either method, but ultimately you want your code to be easy to understand.
You may use
&&
for Single Conditional Rendering
function BookingPage({ loading }) { return ( <div> <h1>Dashboard</h1> {loading && <p>Loading the page...</p>} </div> ); }
​

useContext Hook

Let's return to our Amazon example with sellers and purchasers. How do we track whether a user is a seller or purchaser? How does our system identify the current user? We need to store this information and make it accessible to other components in our application.
There are a few ways to store the user role:
Local state (
useState
)
Props
Context API (
useContext
)
Using
useState
would not be an effective method here. It only works within a single component and doesn't maintain state across different pages.
Props
can pass the role down through components, but this leads to prop drilling.
The
useContext
hook is the best choice in this situation. It is a hook that manages state globally, meaning it provides a centralized way to store user role information and make it accessible throughout the app without prop drilling.
Let's look at an example. Imagine we have 5 nested boxes, and we need to pass information from the outermost box to the innermost one, as shown here:
One way is to do it using Props:
App.jsx
We have a variable named "name" with the value "Muath". We pass this value to the Box1 component.
const App = () => { const name = "Muath"; return ( <div className="flex justify-center items-center h-screen bg-gray-100"> <Box1 name={name} /> </div> ); };
​
Box1.jsx
Box1 receives 'name' as a property and displays "Box 1 - Hi {name}" within its content. Then we pass this value to the inner box.
const Box1 = ({ name }) => ( <div className="p-6 border-4 border-red-500 rounded-lg"> Box 1 - Hi {name} <Box2 name={name} /> </div> );
​
Box2.jsx
Box2 receives the 'name' property and forwards it to the inner box.
const Box2 = ({ name }) => ( <div className="p-6 border-4 border-yellow-500 rounded-lg"> Box 2 <Box3 name={name} /> </div> );
​
Box3.jsx
Box3 receives the 'name' property and forwards it to the inner box.
const Box3 = ({ name }) => ( <div className="p-6 border-4 border-green-500 rounded-lg"> Box 3 <Box4 name={name} /> </div> );
​
Box4.jsx
Box4 receives the 'name' property and forwards it to the inner box.
const Box4 = ({ name }) => ( <div className="p-6 border-4 border-blue-500 rounded-lg"> Box 4 <Box5 name={name} /> </div> );
​
Box5.jsx
Box5 receives the 'name' property and displays "Box 5 - Hi {name}" within its content.
const Box5 = ({ name }) => { return ( <div className={`p-6 border-4 border-black text-black rounded-lg`}> Box 5 - Hi {name} </div> ); };
​
As you can see, passing values through props can become messy. When components receive data through props (like a
name
string), they get these values as function parameters. Remember that props are immutable—child components cannot modify them.
Let’ check how to do the same thing with useContext.
Creating the Context
For a clear project structure, create a directory called "context" and inside it create a file named
NameContext.jsx
at
/src/context
.
To create context, you must Import 
createContext
 and initialize it:
import { createContext } from "react"; const NameContext = createContext(); export default NameContext;
​
Providing Access Across the Component Tree
Since we have boxes nested within boxes, our component tree looks like this:
App └── Box1 └── Box2 └── Box3 └── Box4 └── Box5
​
Since App is our root component and we want to provide access to all components beneath it, we need to import
NameContext
. Then in the return statement, we wrap our content in
<NameContext.Provider
and pass it our value. In this case, the value is a variable called name. We use the same code as before and close it with
<NameContext.Provider>
. In this way, all components have access to the data.
import {useState} from "react"; import NameContext from "./context/NameContext"; import Box1 from "./components/Box1"; const App = () => { const [name, setName] = useState("Muath"); return ( <NameContext.Provider value={name}> <div className="flex justify-center items-center h-screen bg-gray-100"> <Box1 /> </div> </NameContext.Provider> ); }; export default App;
​
To access a variable stored in another component, we simply need to use the useContext hook with the appropriate Context name—in this case,
NameContext
. The variable 'name' will store the context value.
import React, { useContext } from "react"; import NameContext from "../context/NameContext"; import Box2 from "./Box2"; const Box1 = () => { const name = useContext(NameContext); return ( <div className="p-6 border-4 border-red-500 rounded-lg"> Box 1 - Hi {name} <Box2 /> </div> ); }; export default Box1;
​
Since Boxes 2 through 4 don't use the context value, they don't need to import the context-related dependencies.
import React from "react"; import Box3 from "./Box3"; const Box2 = () => ( <div className="p-6 border-4 border-yellow-500 rounded-lg"> Box 2 <Box3 /> </div> ); export default Box2;
​
import React from "react"; import Box4 from "./Box4"; const Box3 = () => ( <div className="p-6 border-4 border-green-500 rounded-lg"> Box 3 <Box4 /> </div> ); export default Box3;
​
import React from "react"; import Box5 from "./Box5"; const Box4 = () => ( <div className="p-6 border-4 border-blue-500 rounded-lg"> Box 4 <Box5 /> </div> ); export default Box4;
​
Here we use the same imports as Box1 since we need to access the context value.
import React, { useContext } from "react"; import NameContext from "../context/NameContext"; const Box5 = () => { const name = useContext(NameContext); return ( <div className="p-6 border-4 border-black text-black rounded-lg"> Box 5 - Hi {name} </div> ); }; export default Box5;
