Working with Events and State

Working with Events and State

Theory

We have gained knowledge about building and using React components with different properties. However, a React page with only components, no state, and no events is like a mannequin in a store window—dressed up, perfectly posed, and looking great, but completely unresponsive. While it may be a masterpiece of design, try interacting with it and you'll get nothing but a silent stare.

Handling Events

What are events in React? No, we're not talking about parties! We're talking about something quite different. Events are actions that occur within your program that the system can detect and notify you about. For example, when a user clicks a button on a webpage, you can program your code to respond by showing an information box.

Let's look at an example of when and why to use
onClick
. Consider a dark/light mode feature on your page with a moon icon in the top right corner. When users click the button, nothing happens. Why? Because we haven't added an event listener to the button. Currently, we only have a basic button like this:
<button>Dark Mode</button>
​
We need a way to detect when users press the button and respond accordingly. This is where events come in. To enable this feature, we need two things: an event handler to detect the button click, and a function that contains the code for what should happen after the button is pressed.
import { useState, useEffect } from "react"; function ThemeToggle() { function setDarkMode(){ console.log("Button clicked!"); } return ( <div className="flex items-center justify-center min-h-screen"> <button onClick={setDarkMode}> Switch to Dark Mode </button> </div> ); } export default ThemeToggle;
​
As you can see in the code above, we have a function called
setDarkMode
. The button implementation is now more complex than before. When the user clicks the button, the
setDarkMode
function is called. Simple, right?
<button onClick={setDarkMode}>Switch to Dark Mode</button>;
​

Login form

Let's create a simple login page with two input fields: one for email and another for password. As you may remember from the HTML lecture, we can specify the type of input field. When you set the type to email, it automatically validates that the user enters an
@
symbol.
This is a simple React component. Currently, when you press the button, nothing happens. Let's modify the code to print the values to the console.
function Login() { return ( <> <h2 className="text-center text-lg font-semibold mb-4">Login</h2> <form className="space-y-4"> <input type="email" placeholder="Your email" className="w-full p-2 border rounded" /> <input type="password" placeholder="Your password" className="w-full p-2 border rounded" /> <button type="submit" className="w-full bg-blue-500 text-white p-2 rounded" > Login </button> </form> </> ); } export default Login;
​
While one approach would be using the DOM, this won't work in React. Instead, we can use a function that handles user input changes and stores the values in variables using
useState
.
import { useState } from "react"; function Login() { const [email, setEmail] = useState(""); const [password, setPassword] = useState(""); const handleSubmit = (e) => { e.preventDefault(); console.log("Email:", email, "Password:", password); }; return ( <h2 className="text-center text-lg font-semibold mb-4">Login</h2> <form onSubmit={handleSubmit} className="space-y-4"> <input type="email" placeholder="Email" value={email} onChange={(e) => setEmail(e.target.value)} className="w-full p-2 border rounded" /> <input type="password" placeholder="Password" value={password} onChange={(e) => setPassword(e.target.value)} className="w-full p-2 border rounded" /> <button type="submit" className="w-full bg-blue-500 text-white p-2 rounded"> Login </button> </form> ); } export default Login;
​
Let's break down the code step by step. First, we have something new in the code: the email and setEmail variables. These come from
useState
, which is a React hook. While we'll cover hooks in detail in a later lecture, for now we'll focus on
useState
. Like props, state is a key concept in React—but while props handle external data coming into a component, state manages and updates internal data.

Updating values

Let's break down this code. We start with
const
, which declares a variable. After
const
, we have square brackets containing two values:
email
(our variable name) and
setEmail
(a function that updates the email value). Then we have
useState("");
where the empty string
""
sets the initial value.
To change the value of the email variable, we simply call the
setEmail
function with the new value, like this:
setEmail("Muath")
.
const [email, setEmail] = useState("");
​
Why not use a regular variable instead? Because the UI wouldn't update when the user types.
useState
remembers the value and automatically updates the UI whenever it changes.
const handleSubmit = (e) => { e.preventDefault(); console.log("Email:", email, "Password:", password); };
​
Next, we have an arrow function called handleSubmit that takes a parameter
e
. This
e
is the event object which contains details about the event that React automatically passes when the form is submitted. The function calls
preventDefault();
on the event object, which stops the page from refreshing—the default behavior when submitting a form. Finally, we use
console.log
to display the email and password values in the browser's console.
This function is used within the form's onSubmit attribute. When users press the submit button, the function executes.
<form onSubmit={handleSubmit} className="space-y-4">
​
Another approach is to remove
onSubmit={handleSubmit}
from the form and instead add an
onClick
handler with the function to the button.

Input element

The input element is no longer as simple as before. Now we need to listen for when users start typing in the input box and update the variable each time they press a key.
<input type="email" placeholder="Email" value={email} onChange={(e) => setEmail(e.target.value)} className="w-full p-2 border rounded" />;
​
We have added two key attributes here: value and onChange. The value attribute is set to email, which we defined earlier using useState with an empty string as its initial value. When the user types something new, onChange detects the input and React compares the new value (
e.target.value
) with the current state (
email
). If they differ, onChange triggers a state update, causing React to re-render the component. Here you can learn more about the Event object.
Let's examine what happens inside the onChange event handler:
This is an arrow function that takes the event object
e
as an argument.
e.target
refers to the HTML element that triggered the event (the input field).
e.target.value
is the current text inside the input field. It updates the state variable
email
with the new input value.
To make debugging and testing easier, or if you need to verify that your code is working correctly, you can display the email value directly in your component by adding
{email}
like this:
return ( <> <h2 className="text-center text-lg font-semibold mb-4">Login</h2> <form onSubmit={handleSubmit} className="space-y-4"> <input type="email" placeholder="Email" value={email} onChange={(e) => setEmail(e.target.value)} className="w-full p-2 border rounded" /> <input type="password" placeholder="Password" value={password} onChange={(e) => setPassword(e.target.value)} className="w-full p-2 border rounded" /> <button type="submit" className="w-full bg-blue-500 text-white p-2 rounded"> Login </button> </form> <h1>{email}</h1> </> );
​
With each change, the onChange event is triggered, and if everything is working correctly, we can see the updates reflected in the h1 element. This demonstrates how easily we can display JavaScript variables in our HTML.
